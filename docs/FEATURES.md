# ZeroField feature reference

The full list of what this checkout does, with each feature's limits. The [README](../README.md) has the short version.

## Features

The target is an open-weights filmmaking and V2V studio; this checkout delivers a **bilingual production workspace with inline video review, configurable Comfy workflows and a planning crew that runs on a local open-weights model**. The crew and provider work of [SPEC_20](specs/SPEC_20_PLANNING_AGENT_LAYER_AND_PROVIDER_PRINCIPLES.md) is implemented and has had a first run on a real GPU with the local model; that run found open break points in the new-production path: see [the verification history](VERIFICATION_HISTORY.md).

- English / Traditional Chinese studio navigation, crew settings, annotations, asset review, and agent controls. English is the first-run default.
- The [Story Workbench](STORY_WORKBENCH.md): five navigation entries, script confirmation/breakdown, scene-grouped galleries, wardrobe variants, candidate selection, card/node overrides, split/merge, batch generation and episode film export over `/aivideo/open/v1`.
- Three creative spaces on productions that have a cinema slate, behind one breadcrumb menu (Ctrl 1 / 2 / 3) with a scene · shot focus that travels between them and floating panels you can hide: **Story & World** (the writing workspace: the script with its stable outline, creative versions and the shots an edit would leave out of step; and the Cast & sets wall), **Shot Stage** (crew proposals reviewed on their shot, a draggable 3D plan with a beat track and easing curve, stored on the server with a revision number), and **Timeline** (frame-accurate per-shot trims with ripple or roll, a cut preview, and a film export that honors the trims). Built on a small control kit (parameter rows, range sliders, timecode fields, curve editor). Gaps are listed in [SPEC_15 §6](specs/SPEC_15_UNIFIED_CREATIVE_WORKSPACE_UI_DESIGN.md): no write-back from shots to script lines, no audio tracks or J/L cuts, no razor, and the Timeline's "runs long" hints are a local rule, not an agent.
- SPEC_18 refinements inside those spaces: on the Cast & sets wall pictures generate in the background (several at once, each with cancel and retry, picked up again after a reload) and the card you pick opens in a large editor laid out like RunningHub's character editor (the picture beside all of its pictures, a strip of looks with a + for another one, the description as the biggest box, and one row of generation choices that shows the time earlier runs took or "time unknown"; voice, status and notes fold into a More section); the primary button opens a build/update dialog with per-mode shot estimates; Shot Stage detail shows the previs → first frame → video ladder and each shot's cast, whose look menus rewrite only the `@code` in the prompt. A production can also start from a story: the New Production dialog takes an idea, a novel chapter or a screenplay in one box, with a ratio and a style, and opens Story & World with it in the writing workspace (an idea or novel as a private source, a screenplay as the working script when empty, or a private draft rather than overwriting occupied content). Not built: voice audio and a generation line on shot detail ([SPEC_18 §11](specs/SPEC_18_RUNNINGHUB_INFORMED_STUDIO_REVISION.md)); character three-views came later with SPEC_21 (below).
- **Asset-first production** ([SPEC_21](specs/SPEC_21_ASSET_FIRST_PRODUCTION_AND_UPDRAFT.md)). Every character, set and prop is a locked text description plus pictures, and each picture has one job. A character has a face close-up, a full-body front that the server crops below the chin (so the model never sees a small face it could copy into wide shots), a back rendered from the face, and a sheet the server composes from the three; sets have a plate, a location map and one light logic; props have a product shot and a shape lock, and each state (a lit and a dead burner) is its own asset, edited from the base picture. A stress test renders the asset in new poses, light and company and shows how many of the results are still recognizable. For each shot the compiler writes a reference plan (up to six pictures, each with its purpose: face, body, location, prop) for the FLUX 3 Klein first frame, and a fixed video skeleton for LTX-2.5 (exact head count, location map, optics, timed action, physics, one light, an audio lock where only quoted lines are spoken); when a prompt runs over budget whole blocks drop in a fixed order and the preview shows what was dropped.
- [SPEC_19](specs/SPEC_19_SHOT_COMPOSER_ADOPTION_AND_FILM_PANEL.md) adoption and the film panel on the Shot Stage: a picked shot opens in a **composer** (the current take on top; **Reference** and **Camera** buttons open an example wall in its place, camera body, lens and aperture write `Optical Rig`, camera moves go into the prompt as `#tags` expanded in place; the prompt is the largest input, with inline `@` asset, `#` move and `@SC01-S02.end` cross-shot tags, a read-only view of the exact compiled prompt, and one row for output, workflow, seconds, 1–4 takes and the estimate). One ✓ (or `A`) adopts a take, story candidate or pending pipeline proposal, writing the media and Approved in one table edit; later takes never overwrite an adopted shot. The right column shows the shot in the cut: neighbours, a progress bar with seam dots, the takes, trim, the references it quoted and "upstream changed". A cut check sets the outgoing and incoming frames side by side for the Continuity Supervisor, queued behind renders. The film window counts adopted shots, fills gaps with the latest take, previs or nothing, can play only the seams, lets you try a take in the cut without writing anything, and exports `selection: "adopted"` with each segment's take, in/out points, references and cut result. Film setup (genre, image era, tempo), palette and lighting are three more buttons with their own walls; the episode sets defaults on an **Episode look** page (opened from the ratio and style tile in Story & World) and a shot can override any of them (本集 / 本鏡 on the button, Back to episode clears it). They compile into `Film:`, `Color:` (with the palette's hex codes) and `Lighting:` lines, the same text on the Story API and the M8 pipeline ([receipt](spec19-verification.json)). Every look and camera option has a sample: FLUX 3 Klein stills of one original test scene and camera-move loops rendered by the 3D Stage, each with its seed, prompt and licence in `ui/public/assets/look-samples/manifest.json`. Not yet: OpenJutsu in the composer; no crew tool proposes a look yet; the M8 pipeline path does not resolve cross-shot references; cut checks and generation were exercised with stand-in models only.
- The [writing workspace](WRITING_WORKSPACE.md) (SPEC_16) adds recoverable private sources/drafts, scene/plot editing, immutable creative versions, compare/adopt, selected-shot story impact, shared narrative notes, safe literal replacement and TXT/MD/DOCX / browser-print handoff. Saving text never generates media. In the three-space studio it is the editing face of Story & World's By scene view ([SPEC_16A](specs/SPEC_16A_INTEGRATION_INTO_THREE_SPACE_STORY_WORLD.md)).
- Nineteen built-in Studio Cards (twelve existing plus seven official native Router models) and authenticated persistent ComfyUI JSON / RunningHub curl imports. [Router protocol and limits](COMFY_ROUTER.md) are separate from workflow-graph execution.
- The [lean Agent Console](SPEC08_CONSOLE.md): exactly twelve functional pages, twelve templates/blank/literal drafts, seven governed Studio/advisor tools, versioned skills/scoped memory, isolated outcome grader, existing M8 sessions and manual/cron deployments, provider/environment references and combined truthful analytics/active limits. Independent review is pending; fixture engineering proof is not semantic-quality or billing acceptance.
- **Crew planning jobs** ([SPEC_20](specs/SPEC_20_PLANNING_AGENT_LAYER_AND_PROVIDER_PRINCIPLES.md)). With a model ready, built-in crew roles write proposals where rules and templates used to decide alone. The Cinematographer writes a timed beat sheet into a shot's Action & Audio Prompt, picks its camera and lens (a ghost camera appears on the 3D Stage); Art (it runs on the Screenwriter's profile) writes locked appearance descriptions and new looks and works out who is in each shot or scene; the Screenwriter offers adaptation and shot-breakdown candidates in the script view, each with its storyboard impact beside the always-listed rule version. Every job has a JSON schema, a validator in code, at most one retry and a rule fallback (marked `rule_fallback`). The output is always a proposal: a single-cell table proposal locks only its target cells, so several can wait on one page, and nothing is written until a crew member adopts one. The crew never submits paid or closed generation. With no usable model a request answers 409 `DRAMA_CREW_NOT_READY` and writes nothing. Ask from the shot detail (**Ask the crew**), the Story & World asset card or the script view; jobs appear on the Agent Board with a cancel button, under a readiness banner that names what blocks the crew (worker off, Ollama unreachable, model not pulled, policy or price limits) and how to fix it. Code: [`crew_jobs.py`](../project_assistant/crew_jobs.py), [`story_crew.py`](../project_docs/story_crew.py). A pre-production flow chains the roles (Screenwriter, Art, Cinematographer, Continuity) with a human lock between stages (script, list, storyboard), starts from a "let the crew pre-produce" card once a storyboard is built, and runs the continuity check as a job.
- **3D plans the crew can edit.** The Stage's per-shot plan is stored on the server with a revision (a stale save is refused with 409 `DRAMA_PREVIS_REVISION_CONFLICT`, and the Stage offers reload or overwrite) and names its cast by `@CAST` code; a Stage button writes the plan's lens and camera motion back into the slate's Optical Rig and Camera Motion cells. The `propose_previs_ops` tool takes structured operations (`place`, `camera`, `retime`; at most 32) and a deterministic solver turns them into a plan, never code written by a model. The solver is the Stage's own JavaScript (`ui/src/previs/ops.js`), run on the server in a headless Edge or Chromium on SwiftShader (CPU, no network), which also renders a six-frame contact sheet for the proposal; set `ZEROFIELD_PREVIS_BROWSER` to pick another browser or `off` ([worker setup](WORKERS.md)). With no browser the proposal keeps only the operations, the Stage solves them when you review, and a proposal without a solution cannot be approved. Such plan and camera proposals are `shot_meta` proposals reviewed on the 3D Stage, not in a table. Not built: a server-rendered WebM preview (the contact sheet only).
- **Provider tiers, failures and the GPU.** Agent models are sorted by `project_assistant/provider_catalog.json` into `local_open`, `hosted_open` and `closed`: `open_weights_only` allows only the first, hosted open weights also need a showrunner's switch (off by default), closed models need `hybrid_studio`, and `OPENBENCH_PRODUCTION_POLICY` caps the agent models as it caps media. The ledger records the model that actually answered; failures are classed (local, quota, auth, provider, timeout, empty, output, GPU busy) and shown in plain words. A failed call no longer locks the crew: local failures settle at once, a call whose result is unknown keeps its slot for 600 seconds by default and a showrunner can reconcile it in the Agent Console. Continuity grading and the Quickstart builder run under the same governance, and a cross-process GPU arbiter (a PostgreSQL advisory lock per GPU host) serializes ComfyUI renders, grading and local model calls ([worker setup](WORKERS.md)). The ChatGPT subscription endpoint was removed.
- **Agent Console operations** (SPEC_20 R36 to R41). On Providers & API Keys, a model setup check tries the configured model with a chat, a tool call, a JSON-schema reply and an image, confirms it exists and shows its context length, and **Roles and models** lists what each role may use with its tier and holds the hosted-open-weights switch. The Dashboard has an automation switch (it holds automatic grading, crew pre-production jobs and scheduled deployments; work you start by hand still runs), a GPU panel (video memory, ComfyUI queue, loaded models) and a queue panel (chats, dispatches, worker failures and uncertain reservations of the production, with reconcile). Environments & Bridges has the External agents section described below.
- **Workflow manuals and evaluation.** [`skills/`](../skills/README.md) holds four step-by-step manuals (crew pre-production, shot beats, 3D blocking, continuity check) that the `get_workflow` tool returns; the tools enforce scope, review and spending limits whether or not a manual is followed. An offline tool-surface audit (`python -X utf8 scripts/audit_tool_surface.py`) lists every tool the built-in crew, MCP and ACP can see and fails on any change to the checked-in list. A crew evaluation set ([`research/crew_eval/`](../research/crew_eval/README.md), `scripts/crew_eval.py`) has eight hard cases each for beats, blocking and continuity, with reference answers and a scorer; the tests check that the reference answers score 100%. Against local `qwen3.8:27b` (2026-10-27) the beats set scored 18.56% and the continuity set 24.29% (2 of 8 cases each passed every hard check); the blocking set has no crew job to run yet.
- [SPEC_07 routing and allocation](SPEC07_STUDIO_ROUTING.md): default open-weights policy lock, explicitly authorized hybrid graphless providers, source-bound batch allocation, real structural preparation and reviewed M8 media races/two-stage handoffs. Resource estimates are uncalibrated, not savings or quality promises.
- A `ZeroField Studio` template with five editable pages: **Director Brief**, **Soul Cast**, **Cinema Studio**, **OpenJutsu Lab**, and **Comfy Pipeline**.
- **Updraft** showcase, seeded by the launcher from `samples/updraft/production.json`: a one-scene, ten-shot production with locked cast, location and prop assets (including a lit and a dead burner state), the film look, and a shot slate. Its media (asset panels, first frames, takes and the exported film) were rendered through ZeroField with FLUX 3 Klein and LTX-2.5 and are filled in from `samples/updraft/manifest.json`; the adopted takes are seeded as approved, so the film window opens at 10/10 ([how each file was made](../samples/README.md)). Raw project templates retain empty media cells.
- Inline video controls and hover previews, cached metadata, candidate video comparison, and visual input/output chains with resolved `@Asset` references.
- Single-shot comparison, keyboard shot stepping and optical/motion/mode presets alongside Studio Assistant; selected shots and individual stages run in the current sheet.
- Standard reference packs: source video, extracted PNG frame, continuous motion guide, anchor keyframe, multiple `@Asset` images, prompt and seed.
- FFmpeg first-frame extraction, edge/luminance/frame-difference motion guides, and split-screen output with audio and faststart.
- OpenJutsu **Object Swap** rows: a FLUX 3 Klein swap key, then one LTX-2.5 graph that runs the Alpha-Gen IC-LoRA matte, regenerates the subject and composites it over the source ([workflow](../workflows/README.md#openjutsu-subject-replacement-object-swap)).
- Cinema **Layout Render** from the 3D Stage: the previs and its actor matte drive the LTX-2.5 Layout-To-Render IC-LoRA after a reviewed FLUX 3 Klein key of frame 0, keeping the blocked set and camera ([workflow](../workflows/README.md#layout-render-3d-stage-previs-as-an-ic-lora-layout), [S03 in the app](verification/motion-lab/app_layout_lane_s03.jpg)).
- **Chained Layout Render for long takes**: add **Chain In Frame**, **Mid Key** and **End Key** image columns to a Cinema Studio row and its Layout Render starts exactly on the previous slice's last frame (`LTXVImgToVideoInplace`) and is guided through a mid keyframe and onto a planned last frame (`LTXVAddGuide`); rows without them render as before ([`layout_guides.py`](../project_assistant/studio/layout_guides.py), [workflow](../workflows/README.md#layout-render-3d-stage-previs-as-an-ic-lora-layout)). The 88 s **[Updraft one-take](../samples/updraft/updraft_oner.mp4)** is nine such slices from one Blender previs camera, a circle-to-circle push-through composited from LTX image-to-video plates (pupil → rock pool → moon → sun → balloon), the takes' own LTX sound and an ACE-Step 1.5 score, all open weights in local ComfyUI; the scripts are in [`tools/oner/`](../tools/oner/README.md).
- **Camera fidelity** in shot review: every video take in a row with a Previs is scored in the background against it (Lucas-Kanade + RANSAC camera path), with tilt / pan / zoom travel as a fraction of the previs move; needs `.[fidelity]` (OpenCV, NumPy) ([S03](verification/camera-fidelity/s03_shot_review.png)).
- **Continuity grades** in shot review: the Continuity Supervisor's vision model grades a take's 8-frame contact sheet (score, issues, notes), optionally for every take as it lands. Grading waits for running ComfyUI renders and frees ComfyUI's models; the vision model stays loaded for further model calls and is unloaded (`keep_alive: 0`) before the next render; grades are information only: a failing grade carries a rewritten prompt, and **Retake with this prompt** writes it into the shot and re-renders in one click ([verification](PHASE2_PROGRESS.md#continuity-grades-in-the-product)).
- Arbitrary external ComfyUI JSON slot binding through `input_bindings`, including dot paths and optional media; local ComfyUI or official Comfy SDK execution with separate Cinema and V2V worker routing.
- Documents, typed tables, gallery and board views, source-file import/export, revisions, and scoped editing proposals.
- The inherited M8 agent system: configurable roles and tools, persistent tasks and dispatches, decision gates, candidate comparison, batch row assignments, and the ACP stdio bridge.
- English statuses with compatibility for existing Chinese status values and legacy tool actions.

The default crew agents are Showrunner, Screenwriter, Cinematographer, and Continuity Supervisor. Candidate proposals are applied only after review. Existing authentication, permissions, stable row/column identities, and lease protections remain in place.

Use **English / 繁體中文** in the top bar to switch the interface. The same preference applies to sign-in and access-error pages and survives a reload. Switching preserves unsaved table / assistant drafts and does not translate or rewrite project titles, documents, prompts, custom agent names, or saved workflow definitions. The studio template and its example content remain English.

Translations live in `ui/src/i18n/locales/en.json` and `zh-TW.json`. Add semantic keys to both dictionaries, including matching interpolation parameters. Use fixed IDs and `normalizeStatus()` for application logic; use `statusLabel()` only for display. Legacy Chinese status values and tool action keys remain valid. API errors retain their original `error` and policy `code`, with additive `message_key` / `message_params` for localized presentation; unknown errors retain a readable fallback.

## Generation setup and limits

The bundled [FLUX 3 Klein and LTX 2.5 workflows](../workflows/README.md) use open-weights model graphs and documented node dependencies. Install the listed weights/custom nodes in your Comfy deployment before generating. The official Comfy SDK remains the workflow-capable Developer Platform route. The separate official native Router model driver cannot execute arbitrary workflow graphs. It uses **POST `/estimate`**, not `/price`; even exact estimates are not price locks. Hard is the default and refuses unlocked charges. Only explicit versioned current-admin estimate-soft consent permits estimate-risk admission; overages remain visible, and provider reports are not invoices. Open-only stays local by default; hosted Router also needs explicitly authorized hybrid, current environment/credential grants and a fresh exact-input-bound quote.

Model quality has not been benchmarked. OpenJutsu provides source-guided V2V restyling with a reference image. Rows whose **Jutsu Mode** is `Object Swap` use an LTX-native subject replacement instead: the Alpha-Gen IC-LoRA mattes the subject, LTX-2.5 regenerates it from the FLUX 3 Klein edited first frame, and the result is composited inside the grown, feathered matte over the untouched source pixels, keeping the source audio. [Two RTX 4090 renders](verification/openjutsu-swap/README.md) ran it, one through a lab driver and one through the Comfy SDK and comfy-api-proxy. Limits: Alpha-Gen mattes the whole foreground, so a shot with several people cannot pick one; clips are capped at 145 frames; higher denoise follows the new identity more closely but follows the source motion less (at 0.85 a held prop can disappear); the background inside the matte is regenerated too and drifts from the source at higher denoise (seams show at 0.9). The Clean-Plate IC-LoRA and depth conditioning are not wired. The [Updraft media](../samples/README.md) are real FLUX 3 Klein and LTX-2.5 renders, original and CC0; they do not exercise OpenJutsu. The older `samples/cast_kael.png`, `set_observatory.png` and `shot_s01.mp4` are procedural placeholders kept for tests, not model renders. `luma_depth` is a luminance structure proxy, not learned depth estimation. The sample V2V graph exposes a motion-guide upload slot; using that guide as model conditioning requires an externally authored compatible control graph.

## Other crew models

The default and the contest demo path use local open weights only. To use a different local server that speaks the OpenAI chat-completions protocol (vLLM, llama.cpp server, LM Studio), set `OPENBENCH_API_BASE` (the base URL including `/v1`) and `OPENBENCH_MODEL`. The default sends `reasoning_effort: medium` only for the complete local default; with a custom endpoint or model none is sent unless you set `OPENBENCH_REASONING_EFFORT` to `low`, `medium` or `high` (not every model accepts the field). See [worker setup](WORKERS.md) for these settings, GPU sharing with a separate worker and ACP configuration.

Hosted endpoints such as OpenRouter and closed models (OpenAI, Anthropic, Gemini) are optional and outside the demo path. A showrunner has to allow the host in Agent Console → Environments & Bridges, add the key variable name to `OPENBENCH_AGENT_KEY_ENVS` where the server starts, and set a price ceiling for the model in Spend & Rate Limits. Closed models are for hybrid productions only. Hosted open weights (for example `qwen/qwen3.8-27b` on OpenRouter, listed in `project_assistant/provider_catalog.json`) additionally need the hosted-open-weights switch in Agent Console → Providers & API Keys → Roles and models (stored as `provider_policy.hosted_open_enabled`, off by default; it never opens closed models). An endpoint the catalog does not list counts as closed. The same page has a model setup check that tries the configured model before you rely on it. In Environments & Bridges, switching an environment from `restricted` to `allowlist` drops its automatic allowance for this computer, so list `127.0.0.1` and `localhost` next to the hosted host. One hosted open-weights model has been used for real: DeepSeek V4.1 Flash 1017 on OpenRouter ran the crew and continuity grading in the 2026-10-28 walk (see [the verification history](VERIFICATION_HISTORY.md)). Closed models have only been tested against fake endpoints. For contest workflows, use open-weights models and open-source nodes.

## External workflows and reference preparation

The seeded OpenJutsu slate includes independently replaceable **Source Driving Video**, **First Frame**, **Motion Structure**, **Anchor Keyframe**, **Remastered Video** and **Split-Screen MP4** cells. The preparation stages use the original source video. Each result is reviewed before downstream generation proceeds.

Use a trusted JSON file with `--worker-config path/to/studio-workers.json` to override stage adapters (`image`, `cinema`, `v2v`, `extract`, `structure`, `split`, `assemble`) or provide an `anchor` image-edit adapter. Workflow paths resolve relative to that file. For example, an externally authored image-edit graph can bind its own pose/reference slots:

```json
{
  "anchor": {
    "image_gen": {
      "adapter": "comfyui",
      "platform": "local",
      "base_url": "http://127.0.0.1:8188",
      "workflow": "./my-image-edit-api.json",
      "output_node": "save",
      "input_bindings": {
        "first_frame": {"node": "pose", "input": "image", "upload": "image"},
        "asset_images.0": {"node": "identity", "input": "image", "upload": "image"},
        "compiled_prompt": {"node": "prompt", "input": "text"},
        "seed": {"node": "sampler", "input": "seed"}
      }
    }
  }
}
```

Node names in this example belong to the external graph and must match its actual API JSON. ZeroField uploads and binds slots; the graph defines how references condition the model. The text-only cast generator is not used as a substitute for an image-edit anchor workflow. If you customize the saved pipeline, add/bind the matching stage through Pipeline Settings.
