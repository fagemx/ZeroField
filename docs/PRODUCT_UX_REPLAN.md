# OpenBench：從展示原型到日常工作台的設計重整

日期：2026-10-16。使用者已授權「照你研究的規劃內容開工做完」，現已進入實作與操作走查。實作裁定、證據與限制見 [UX_IMPLEMENTATION.md](UX_IMPLEMENTATION.md)。本文件保留研究及設計依據；使用者日常試用仍須另行記錄，不能由代理測試替代。辦公、美術及自由組裝工作流都涵蓋。

同日設計修訂：依使用者指定的 `taste-skill` 重新檢查工作區比例、視覺層級及操作連續性，見第 12 節。第 6／7 節的面板為按需展開，不能全部常駐；核對長內容時由中央工作區承接。

## 1. 這次要解決的問題

現在有文件、表格、代理、工作流和版本 API，但使用者要付出太多理解與操作成本，尚不足以每天拿來工作。M0～M7 的工程完成保留為歷史事實；功能數量、測試數量與模型跑通，不能當作產品可用性的結論。

研究當時暫停追加展示功能，後由使用者明確授權依本規劃施工。原先三視圖草稿已改為以連續編輯、核對與恢復為主的工作區；歷史 49 項測試不作本輪驗收證據。依序完成資料契約、共用操作及真實瀏覽器走查，實際使用觀察另列。

現有原子提案、版本與列鎖保留。問題在於它們尚未形成可理解、可操作、可恢復的一套體驗，不能直接推翻為「後端全部重做」。

## 4. 三種工作共用的需求

| 使用者正在做的事 | 必須順手的共同操作 | 專屬呈現 |
| --- | --- | --- |
| 整理文件與 Excel、交付結果 | 讀來源、範圍選取、快速修改、核對代理改動、追蹤交接版本 | 公式與工作表、原檔相容性、匯出結果 |
| 管理素材與審核意見 | 批次選取、逐筆比較、看上下文、版本與意見對位、更新進度 | 圖片封面、圖庫、圖片版本比較；影片附件 |
| 自由組裝自動化工作 | 選來源、指定處理範圍、試小樣本、核對結果、修正、重跑失敗部分 | 節點畫布、輸入輸出映射、等待審核、執行紀錄 |

不要求三類工作都經過節點畫布。手動整理與直接請代理協助是完整的工作方式；重複、批次或需要固定步驟時才組裝工作流。

## 5. 先釐清 Excel 與資料表的承諾

「能匯入 XLSX」與「可以像 Excel 一樣工作」是不同範圍。前者不自動包含任意位置表頭、合併格、跨工作表公式、格式保真及結構變更。Teable／Baserow 的一列一筆資料也不能直接代表所有工作簿。

建議原則：一個分頁只有一份可編輯的權威資料。來源檔作交接基準；其他視圖是投影，不能各自複製一份內容。

現有匯入把第一實體列當欄名，畫面資料列號與 XLSX 計算位移不同，流程又有略過首列的假設。下一個模型必須明確保存來源工作表／範圍、表頭位置、資料區、列欄身分與映射版本，不能只靠多加座標例外修補。

| 選項 | 使用者看到什麼 | 代價與選擇條件 |
| --- | --- | --- |
| A：現有資料表＋明確原檔相容範圍 | 同一表格可改資料；超出原檔 Patch 支持時提供「另存新工作簿」或取消／撤回不相容操作 | 新工作簿不保證原檔所有格式；下載來源原檔不包含這次新結構。必須先完成交付能力與提示，不能做到最後才失敗 |
| B：工作簿模型作權威、資料表視圖作範圍投影 | 使用者持續在工作簿上工作，指定其中資料範圍給圖庫、代理及工作流 | 目標是保留工作簿語意；具體公式及格式支援由同一組樣本比較確認。須處理範圍映射、協作及 SDK 授權，尚未選定 |
| C：明確轉成工作台資料表 | 匯入時看預覽，選資料區／標題列；原檔保留作來源，輸出為新整理檔 | 最容易說清能力邊界，但不能滿足持續回寫複雜原檔的需求 |

先拿同一組合成辦公樣本、素材清單及多工作表檔案比較 A／B／C 的操作和交付結果。A／C 是資料整理候選，B 是完整工作簿候選；以日常工作是否順利決定，不因現有程式比較容易改就預先選 A。三者共享的身分、操作與交接契約先釐清，這不是要求使用者放棄 Excel 習慣。

## 6. 表格操作設計

### 工作區配置

```text
專案 / 分頁                          已儲存 · 撤銷 · 重做 · 分享/交接
┌──────────┬───────────────────────────────────┬──────────────────┐
│ 文件與表格 │ 表格 / 圖庫 / 看板  搜尋  篩選  排序 │ 按需開啟的詳情      │
│ 分頁樹     │ 欄名與欄位選單                     │ 依目前選取而變化    │
│           │ 可直接輸入、可框選的資料區           │ 不擋住正在工作的格子 │
│           │                                   │                  │
│           │ 選取：12 列 × 3 欄                  │ 當前一項輔助工作     │
└──────────┴───────────────────────────────────┴──────────────────┘
```

此佈局已用於本輪實作，實際證據見 [實作紀錄](UX_IMPLEMENTATION.md)。預設右欄關閉，表格取得主要寬度；使用者打開詳情／討論／代理時只出現一個輔助面板。低頻工具放欄位選單或詳情；基礎選取、編輯與儲存狀態持續可見。多格差異、長文與圖片版本核對在中央展開，右欄只保留理由或輔助資訊。

### 基本互動契約

| 操作 | 預期行為 |
| --- | --- |
| 單擊儲存格 | 選中、顯示目前座標／欄名，不立即開彈窗 |
| 輸入／雙擊／F2 | 在格內開始編輯；中文輸入法 composition 期間不誤提交 |
| Enter／Tab／Shift+Tab | 提交本格並移至下一個合理位置；Escape 只取消本次編輯 |
| Shift＋方向鍵／拖選 | 看見連續範圍；範圍與列 checkbox 不混為同一件事 |
| 複製／貼上 | 保留矩形；TSV 按欄位驗證並明示轉型，不假設帶來完整 Excel 型態；有篩選、越界或受保護格時先明示範圍；多格一次原子變更 |
| 撤銷／重做 | 對應一次使用者操作；若他人後續已改動，說明衝突，不覆蓋整個分頁 |
| 欄位選單 | 改名、型態、寬度、排序、隱藏、增刪；有公式或工作流依賴時呈現影響 |
| 列詳情 | 同一側欄查看長文、圖片、討論與版本；關閉後回到原選取與捲動位置 |
| 儲存狀態 | 區分尚未提交、儲存中、已儲存、衝突／失敗；失敗內容可保留並重試 |

圖庫和看板建立在這套列身分與欄位操作之上。輕量查看使用列詳情；連續圖片審核可展開為保留列表上下文的工作區：中央看大圖與前版比較，旁側看規範、討論及審核決定，並可上一筆／下一筆。退出後回到原列、篩選及捲動位置。修改狀態不等於批准付費工作流，避免意外執行。

排序預設只改檢視順序，不重寫來源列順序；若使用者要重新排列原檔資料，另作有影響預覽的操作。複製公式要明定相對引用位移與絕對引用保留，不能把文字貼上與公式複製混為一談。這兩項是元件比較時的同一標準。

## 7. 工作流操作設計

### 同屏配置

```text
專案 / 工作流              草稿已儲存                  檢查並執行…
┌──────────┬───────────────────────────────────┬──────────────────┐
│ 分頁樹     │ 讀取工作表 → 整理內容 → 人工核對     │ 步驟：整理內容       │
│           │                       ↓           │ 資料來源 / 處理 / 輸出│
│           │                    寫回結果        │ 目前 1 列樣本        │
│           │ 縮放 · 符合視窗 · 搜尋節點           │ 欄名映射 · 試這一步   │
├──────────┴───────────────────────────────────┴──────────────────┤
│ 本次測試：1 列 · 未寫回    輸入 / 結果 / 問題    查看資料位置        │
└────────────────────────────────────────────────────────────────┘
```

預設以畫布為主，只在選節點後展開必要設定。「試這一步」跟隨選中步驟；測試摘要在設定區內出現，能就地修正再試。底部結果區預設收起，批次結果才展開；深入比較來源／產出時轉為中央寬版工作區，保留流程定位與返回入口。右側設定與代理面板互斥／可切換。不能把同屏理解為分頁樹、畫布、設定、結果全部永久擺滿；寬度與密度需在桌面筆電尺寸實際比較。

### 組裝與執行契約

1. 新增的是「讀取、整理、生成、核對、寫入」等可理解的工作；能力／provider／手腳屬進階設定，不要求一開始填完。
2. 來源選到分頁、工作表、範圍後，立即看到欄名、列數與幾筆樣本；輸出選到具體欄位名稱，不能靠猜第幾欄。
3. 連線要說清楚是「等前一步完成」或「取用前一步的輸出」。若未做資料映射，不以普通連線暗示資料已傳遞。
4. 畫布具備縮放、平移、框選、適合視窗、節點搜尋、鍵盤焦點及撤銷；無效連線當下提示原因。
5. 「試這一步」「從這一步繼續」「執行全部／所選範圍」是不同操作。試跑顯示樣本及副作用，預設結果先核對；需要呼叫外部生成時明示，不能把 dry-run 與真實小樣本執行混稱。
6. 執行前顯示將處理的列／步驟、來源版本、寫回位置、是否要審核，以及缺少的服務；修正入口就在缺項旁。單純排隊成功不顯示為工作完成。
7. 審核位置看得到來源與產出，知道由誰處理、通過哪些列。資料改變後舊核准不能無條件套用；拒絕、取消與未通過列有明確後續。
8. 執行後先呈現結果與可修正問題，進階原始紀錄可展開；點擊失敗列能回到來源格，保留已成功產出，只重跑受影響範圍。

續跑分為「用原設定重試該次執行」與「改設定後建立新執行」，畫面呈現版本差異。試一步明確選擇讀目前表格、指定一次上游結果或手動樣本，顯示資料時間與版本；樣本不能冒充正式來源。缺少必要上游結果或結果已過期時，呈現重新取得／選擇樣本入口，不默默挪用舊結果。成功產出只有在來源、參數與相依未失效時才可重用；目前引擎的整階段等待語意，若要改成某列失敗不阻擋其他列，是 S 階段要驗證的執行契約變更，不能當成只換 UI。

## 8. 代理的操作位置

代理協助放在使用者選取的資料附近。送出前可看見「參考哪些文件」「改哪些列／欄」「預期結果」，選取身分由結構化資料傳遞，不靠文字列名猜測。

建立需求草稿時固定本次範圍；點另一格、切工作表或改篩選只改檢視，不默默改代理的工作對象。使用者可以明確點「以目前選取更新範圍」，先看新增／移除的項目。送出後提案綁定該範圍與來源版本；返回時保留草稿、選取及捲動位置，來源已變更則在原處處理衝突。

結果以「原內容 → 建議內容 → 理由／來源」對照，必要時回到原格查看。相互依賴的新增欄與填值是一組修改；可逐筆接受的修改才提供勾選。核准後保留對照與恢復入口，錯誤在該提案位置呈現，不只跳出短暫 toast。

| D：連貫互動方案 | 下列四組可點擊設計原型及狀態圖，以合成資料製作、與產品分離 | 使用者不靠逐步指路完成一段正常工作及一段錯誤恢復；記錄誤解、繞路與修改，不只詢問外觀感受 |
| S：元件及資料語意實驗 | 相同任務下 grid／workbook 候選對比、React Flow adapter、權威資料與 ID 契約 | 必要互動、中文輸入、撤銷、版本與檔案交付均無未解決阻斷；記錄性能與授權結果 |
| I：共用基礎實作 | 表格基本操作、統一詳情／核對、畫布＋步驟設定及結果 | 三種工作都能完成日常動作；不以其中一種成功代替其他兩種 |
| E：真實工作迭代 | 使用者試用紀錄、前後畫面、問題／修正清單 | 重複使用後仍能完成、理解結果並恢復錯誤，再擴展多視圖與複雜批次功能 |

### D 階段應一次給使用者看的四組畫面

四組沿用同一個合成專案、同一批文件與資料；上一段的選取、修改與版本必須在下一段延續。另以辦公與素材內容交叉檢查通用性，避免做成四個互不連接的示範。原型要能走完操作與恢復分支，並明示哪些運算或服務是模擬。

1. **匯入後整理。** 資料預覽／標題列 → 連續編輯 → 範圍選取與貼上 → 撤銷／匯出影響。需要可操作，不只一張靜態表格。
2. **請代理幫忙並核對。** 從選取資料說明工作 → 核對來源與修改 → 接受一組改動 → 過期衝突與恢復。
3. **素材審核。** 同一份資料的表格／圖庫 → 選一筆看圖與版本 → 留意見／改進度 → 回到原位置；影片不播放。
4. **組裝與修正工作流。** 新增一步 → 選資料與欄名 → 看樣本 → 試一步 → 核對 → 執行所選範圍 → 處理一筆失敗。畫布、設定與結果保留上下文。

### S 階段必測的共同資料

- 200 列 × 20 欄的一般清單，含中文、換行、日期、空值及重複列名；連續編輯、範圍貼上、篩選、復原。
- 多工作表 Excel，含非第一列標題、合併表頭、公式與格式；逐項記錄支持／保留／拒絕，不靜默扁平化。
- 60 筆素材清單，含空圖、不同長寬圖片、長文、舊版本及附件；進度與評語能回到同一列。
- 10 節點流程，含分支、審核、欄位改名、失敗與重試；分別驗證編輯／試跑／正式執行模式。

資料規模是初始評估樣本，不是已證明的容量承諾。速度以相同電腦與樣本測量，再與參考產品比較；不先編造通過百分比。

## 11. 如何討論與修訂

下一輪先由代理提出具體方案與建議，再讓使用者操作四組原型、指出卡住的位置。只追問會改變設計的問題，例如複雜工作簿的使用頻率、保留原格式交件的重要性、平常是否以鍵盤連續整理資料、審核者與流程發起人是否常是不同人。這些問題不作研究開始的阻擋，也不再要求只選一類工作。

每次修訂記錄：**原假設 → 看見的操作問題／使用者回饋 → 調整 → 下一張畫面或下一輪任務**。操作驗收與程式測試分開記錄；任何未實測項目不得打勾完成。

## 12. Taste 校正：先安排注意力，再安排功能

本節依使用者指定的本機參考庫撰寫，屬設計提案。實際讀取 [Redesign Skill](C:/ai_project/taste-skill/skills/redesign-skill/SKILL.md)、[Minimalist UI](C:/ai_project/taste-skill/skills/minimalist-skill/SKILL.md) 與 [截圖批評方法](C:/ai_project/taste-skill/skills/taste-skill/references/critique.md)，並由另一代理獨立檢視流程截圖。這些是開發參考，產品執行不依賴本機 skill 目錄。

### 工作區跟隨任務，而非全部展開

| 正在做的工作 | 中央主體 | 輔助資訊與返回方式 |
| --- | --- | --- |
| 閱讀／整理表格 | 可連續編輯的資料區 | 右欄預設關閉；欄位設定跟欄名走；選取後工具在原有工具列換位，不把表格往下推 |

流程有兩個候選：畫布為主、按需開設定；或步驟編輯為主、畫布作總覽。建議以第一個為預設，保留自由分支與重排的空間；複雜欄位映射／結果核對吸收第二個的寬版工作區。兩者共用選取與草稿，不另建一套只支持線性流程的工具。

### 視覺與動作的具體規則

- **資料優先的密度。** 桌面原型先以資料區從 y=144～176 起始作比較目標，並在 1280 × 720、1440 × 900 及 125% 縮放查看。這是設計起點，不是硬壓尺寸：文字不能變小來達標，窄時明確切換輔助區。表格可水平捲動，整個頁面與工具列不應一起溢出。
- **清楚而安靜的層級。** 保留目前支援繁中的字體與淺色基礎；原型起點為頁名 18～20px、資料／控制 14px、次要資訊 12～13px。數字對齊用等寬數字。必要標籤不能淡到難讀；真正對比度待量測。統一圖示家族，產品導航不以 emoji 當主要辨識，使用者文件內容不受影響。
- **每個當前工作區有明確主動作。** 表格直接編輯時內容是主體，代理入口保留但不壓過資料；單步設定的主動作是「試這一步」，全流程入口是「檢查並執行」。核對時突出「套用選取的修改」，進階選項收在旁，不再並排多個同等深色按鈕。
- **節點保持三級內容。** 動作名稱 → 具名來源與去向 → 當次狀態。模型、Worker、完整指令和 JSON 留在進階設定。選中後清楚指出相關上下游；保存狀態與執行狀態各有位置，不能互相冒充。
- **控制位置穩定。** 選取、保存、錯誤回饋不新增整排高度；儲存格選取與鍵盤輸入立即回應，不等動畫播完。短提示貼近受影響資料，失敗時保留內容與重試入口，不能只靠一閃即逝的通知。
- **動態只解釋變化。** 面板切換可以短暫淡入／位移並支持減少動態；列、格、節點不逐項入場，不改原生捲動慣性。重新排序不偷走選取，返回不重置畫布。骨架只用於初次載入，背景保存保留既有內容。

### 如何用這份 skill

採用：先看畫面再批評、共享對齊線、視覺層級、克制配色、按需展開、完整狀態與固定焦點。保留表格格線與語意狀態色。

依本案任務調整：不採用預設 marketing skill 的圖片數／動畫數配額、網站評獎分數、大標襯線、裝飾背景或大量留白；不把更換字型與圖示當成流暢性的主要修復，也不為美觀隱藏必要動作。沒有執行它面向行銷頁的 lint／inspect 腳本，不宣稱通過其檢查。

下一輪設計審查先看同尺寸畫面及連續操作：第一眼能否辨認資料、選取與下一動作；連改十格是否失去同行參照；改節點並重試是否要重新找位置；核對後是否回到原工作。每輪只收斂最明顯的三個問題，保留修訂前後畫面與未解決事項，再做下一輪。首屏截圖與資料正確性測試各自提供證據，不互相替代。
