# 通用工作台下一階段設計

> **初稿，研究後重新排序。** 使用者最新要求先研究實際可用性，停止追加實作。下列 U1～U4 為功能提案清單，不再直接代表施工順序；依 [研究任務 d-001](../../research/2026-10-16-research-brief.md) 統整後更新。

依據：使用者要求先讓工作台順手，已允許克隆開源參考並依規劃推進；另一位代理的意見作為參考。原始碼查核見 [OPEN_SOURCE_REFERENCES](../../OPEN_SOURCE_REFERENCES.md)。原始 M0～M7 維持歷史工程完成紀錄，以下 U 系列另行驗收。

## 產品決策

主路徑：建立專案 → 匯入文件／表格 → 描述工作 → 核對提案 → 確認寫回 → 匯出交接。行銷、美術、影劇均使用這套能力；範本是起點，不是固定產品流程。

採取漸進整合：保留 Python / PostgreSQL、Tiptap 文件、表格列 ID、提案、版本與 DAG。React Flow 優先做視圖 adapter；TanStack Table 待排序／欄寬／大量資料效能同時需要時做比較實驗。整套 fork Baserow／Teable 會引入資料遷移及第二套應用模型；多平台 API 拼接則增加權限與版本一致性成本，兩者均不作近期方案。

## 全局限制

- 開發限 C:\ai_project\openbench，不讀取原生產環境或公司私有資料。
- 文件／表格／工作流為通用能力，領域範本不新增專用主流程。
- 影片僅作附件與下載，不顯示播放器。
- 視圖切換不複製資料、不新增分頁、不改工作流、不呼叫模型。
- 沿用 React 19.2.0、現有 API、角色檢查、列鎖與版本紀錄；新增依賴先核對套件授權與穩定發布版本。
- 克隆參考庫只作查閱，排除在 Git、Docker 與 Python 封裝；不可直接執行參考庫腳本。
- 所有新增能力分開標示規劃、實作及驗收狀態，不把 mock 模型結果當作真實供應商驗收。

## 分期與交付條件

| 階段 | 使用者得到什麼 | 工程相依與驗收 |
| --- | --- | --- |
| U1 三視圖 | 表格／圖庫／看板切換；選封面與狀態分組；同一列的詳情、選取、搜尋與狀態編輯 | 共用 tablesOf 與 row ID；依原始列座標寫回；空值／自訂狀態不丟列；無狀態欄有引導；無圖片有文字卡。視圖偏好只記於此瀏覽器，不是多人共享設定。 |
| U2 結構與提案 | 自訂狀態、代理新增／改名欄位、逐格 before/after 核對、可靠的選列範圍 | 欄位 ID 與匯入映射先完成；提案綁定 revision、列／欄 ID；新增欄與填值為一組原子提案；刪欄顯示依賴及資料影響。對相依變更不得任意逐格勾選破壞完整性。 |
| U3 工作流操作 | React Flow、只試一個節點／一列、獨立人工審核節點與通過列續跑 | 保留 DAG 協定；單步模式明確限制下游；審核綁定輸入／輸出版本與列集合；拒絕／取消／重複核准／逾時行為皆測試；本輪不重寫已有引擎。 |
| U4 日常交接 | 可儲存自訂範本、助理可用性、兩條完整黃金流程 | 不把內建 worker 關閉誤判為外部 worker 離線；提供設定／等待／不可用狀態；重匯入與匯出證據符合支持界線。 |

先完成 U1 的獨立交付，再做 U2。U3 的畫布 adapter 可先做隔離實驗，但不能繞過審核與版本契約。看板拖曳與多人共享 view 設定排在 U2 穩定欄位 ID 之後；U1 用可鍵盤操作的狀態選單移動卡片。

## U1 互動契約

1. 預設表格；工具列提供三個等級相同的視圖按鈕。切換後搜尋、篩選與已選列保留；篩選改變時清除選取，避免處理不可見列。
2. 圖庫用第一個圖片欄作預設封面，可選其他圖片欄或不顯示封面。沒有圖片也可用文字卡；不把影片網址當作圖片。
3. 看板只允許以狀態型態欄分組，包含嵌入式 status 欄；多個狀態欄可以選擇。無狀態欄顯示「先設定一個狀態欄位」。空值獨立為「未設定」，不悄悄寫成「未開始」。現有未知狀態照樣顯示。
4. 每張卡使用原始 row ID；標題與資料摘要不暴露內部 ID。卡片提供勾選、列詳情及狀態選單；選單修改只寫指定欄，透過現有 table-edit API、base_revision 與後端權限／鎖檢查；失敗不樂觀搬動卡片。
5. 圖片點擊沿用預覽；列詳情沿用討論、媒體版本、代理需求及編輯入口。影片仍為附件。
6. 模式及封面／分組偏好依專案＋分頁＋表格隔離，僅儲存在此瀏覽器。欄位結構改變後重新計算安全預設，避免索引漂移指向不同欄。儲存空間不可用或資料損壞時仍可操作。
7. 視圖函式不改原始 rows，不依可見順序重新計算公式；公式使用完整原表與 worksheet offset。

## U2 契約與施工位置

- `project_docs/doc_schema.py`、`ui/src/editorExtensions.js`、`sheetModel.js`：增加可選 `column_ids`、`status_options`；舊表首次結構修改才補 ID。新欄有新 ID，改名保留，刪除不得復用。重匯入由 `file_handoff.py` 對照前版欄位，歧義先提示，禁止僅靠標題猜測。
- `project_assistant/tool_specs.py`、`tools.py`、`table_edits.py`：新增 `propose_table_schema`；輸入 `tab_key/table_id/base_revision/operations`。operations 支持 add_column、rename_column、set_status_options、delete_column；服務端驗證 role、鎖、欄位依賴與值是否合法。代理只能提案，不能自行 apply。
- `store.py`、`service.py`、`ui/src/assistant/AssistantViews.jsx`：提案以結構化 changes 儲存 row_label/column_label/before/after/operation；核准使用原始 target，不從展示字串還原指令。重讀過期資料、原子拒絕與逐筆選擇的相依限制有獨立回歸。
- `sheetInteraction.js`、`useAssistant.js`：對話帶 `tab_key/table_id/row_ids/revision` 結構化 context；可讀草稿繼續只顯示列名。模型發送前重讀並檢查權限，刪除列明確報錯。
- 驗收以兩人同改同格、改不同格、刪欄後舊提案、重匯入歧義、公式與工作流引用被刪欄影響為核心，不只測新增欄成功。

## U3 契約與施工位置

- 新增 `ui/src/flowCanvasAdapter.js`，`FlowSurface.jsx` 接 `@xyflow/react`。adapter 將現有節點 `id/x/y` 映射至 view，寫回僅改已允許欄位；未知屬性、scope、row_source、target、provider／limb 綁定、edges 均保留。測試 round-trip、連線循環拒絕、唯讀與版本衝突。
- `flow_runner.py`、`http.py`、`tests/test_flow_scopes.py`：增加明確的 `execution_mode: single_node` 與 target node/row；驗證輸入齊全，執行完成後不得自動 enqueue 下游。現有 start_node_id 維持「從這裡開始」語意，避免舊流程變更。
- 獨立審核節點是持久化等待狀態；核准內容包含 run/node/row IDs 與審核時資料版本。只放行核准且版本未變更的列，拒絕列不得送入下游；重啟、重送核准、取消後核准都不能重複執行。
- 跨分支匯流等待所有所需前置狀態，拒絕／空集合有明確終態；通知先用產品內狀態，不擅自傳送電子郵件或外部訊息。

## 黃金驗收流程

**A：日常工作交接。** 匯入測試 Excel＋會議紀錄 → 代理提出新增優先級欄及填值 → 核對原文依據與 before/after → 確認寫回 → 重載 → 匯出。既有公式、支援的樣式與其他工作表保留；超出保真支持的結構變更明確拒絕或告知替代匯出，不能宣稱任意 Excel 無損。

**B：素材審核。** 規範文件 → 資產表 → 圖庫核對圖片 → 看板更新審核狀態 → 單步測試一列 → 審核通過列才續跑。辦公附件與圖片即足以驗收；影片生成／粗剪是另行配置供應商後的選配驗收，不是目前入口，也不恢復影片播放。

兩條流程都要有真實 HTTP／資料庫與瀏覽器證據；付費模型未設定時記錄確定性 fixture 的界線，不以假回覆驗收真實模型連線。
