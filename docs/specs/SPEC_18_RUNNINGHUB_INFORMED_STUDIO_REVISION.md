# SPEC_18 — 借鏡 RunningHub STORY 的工作室改版：看得到進度、代價與關聯（不加步驟條）

> **狀態**：規格草案（2026-10-25），尚未實作。
> **來源**：使用者提供的 RunningHub STORY（`story.runninghub.ai/zh-cn/ai-comic`）入口與流程截圖 18 張，加上對 ZeroField 三個空間的程式盤點。
> **目標**：把 RunningHub 好用的「看得到」做法搬進現有三個空間：生成時不擋人、每一鏡看得到用了什麼、按生成前看得到用哪個工作流程與要多久。不改 SPEC_15 的空間結構，也不重做 SPEC_16 的寫作工作台。

---

## 0. 執行摘要與固定決策

RunningHub STORY 是一條四站的線性流程：

```text
入口（場記板輸入框：一句話創意／匯入劇本檔／匯入 1–100 集影片；比例、畫面風格、導演風格）
  → 劇本（分場大綱＋劇本正文；確認劇本）
  → 設定（自動抽出角色／場景／道具；大圖卡＋右側詳情；背景生成）
  → 拆分鏡設定（AI 拆解或匯入 Excel；分鏡風格、本集目標時長、出片模型檔、單鏡上限）
  → 分鏡（左：這一鏡用了什麼；中：分段鏡頭文字與 @ 標籤；右：結果與歷史；底：膠片條）
  → 短片（截圖沒有點進去）
```

ZeroField 的故事 API 本來就是 RH STORY 介面的本地版（`project_docs/story_openapi.py` 開頭即寫明「RH STORY facade」，見 SPEC_06）。集數、角色／場景／道具、候選圖與選定圖、畫風、比例、批次任務都對得上，`NANO_PRO_G2_I2I_OFFICIAL`、`SEEDANCE_2_FAST_MULTIMODAL_VIDEO` 等代號也已經在 `ALIASES` 對應到我們的卡片。所以借它的介面做法，資料面大多現成。

**固定決策：**

1. **不加常駐步驟條，也不加「確認後才解鎖下一站」的硬閘門。** 保留 SPEC_15 的三個空間、麵包屑空間選單，以及「工作時不常駐切換選項」（使用者決定）；SPEC_16「不新增必經人工閘門」照舊。要借的是看得到進度，不是分頁。
2. **不新增資料模型。** 鏡頭綁定仍是 `cinema-studio` 表 `Action & Audio Prompt` 欄裡的 `@代碼`；素材仍是 `soul-cast` 的列，造型是 `CAST-01:night` 這類變體列；生成仍走既有的 story task、task group 與 flow preflight。
3. **每個畫面仍只有一顆主按鈕（淺色實心，`--primary`；琥珀只標焦點與選取），頂欄常駐控制仍不超過 9 個。** `ui/tests/story-ui.test.mjs` 與 `ui/tests/uiBudget.test.mjs` 的預算不放寬。本規格新增的送出鍵一律用外框按鈕，不用主按鈕樣式。
4. **生成前看得到代價，但不假裝精準。** 本機開放權重卡標「預估時間」，並寫出依據了幾次紀錄；Comfy Router 卡用既有 `router-quotes` 報價，標明「非價格鎖定」；沒有依據就寫「時間未知」或「未報價」，絕不顯示 0。
5. **由便宜到貴看得到，但不擋人。** 預演 → 首幀 → 影片的順序要在鏡頭詳情看得到；缺預演時只提示，不阻止「拍攝此鏡」。
6. **一鏡一個機位不變。** 節奏台修剪、3D 預演、運鏡忠實度都以單一機位為單位；不把 RunningHub「一個鏡頭號＝多切點整段生成」當成鏡頭單位。
7. **內建畫風與導演風格不得使用真實人名。** 依 `docs/DESIGN_AND_DEV_GUIDELINES.md` §3.2：RunningHub 以真實導演命名的風格包不照搬，樣張不得出現真實人物肖像。
8. **雙語與狀態規範照舊。** 新文案只用 `ui/src/i18n/locales/en.json` 與 `zh-TW.json` 的語意鍵，兩邊的鍵與參數一致；狀態邏輯用 `normalizeStatus()`，不新增狀態值（素材「定案」用既有的 `Approved`）。
9. **與 SPEC_16 分工。** 劇本保存、製作基準、改稿影響、具名版本、底部狀態列、DOCX 匯入都歸 SPEC_16；本規格只在「建立／更新分鏡」與新專案入口兩處跟它對齊。

### 0.1 最終交付的三句話

- 「按下生成之後我可以繼續做別的，卡片上看得到哪張在生、哪張好了。」
- 「點開一鏡就知道用了哪些角色、場景、道具和哪套造型，缺什麼一鍵去補。」
- 「按生成之前，我知道會用哪個工作流程、出什麼、大概要多久或多少錢。」

## 1. 參考來源與實際缺口

### 1.1 RunningHub STORY 觀察摘要

| 站別 | 看到的功能 | 版面做法 |
|---|---|---|
| 入口 | 一個場記板輸入框；左側切換「一句話創意／匯入劇本檔（TXT、DOCX、MD、XLSX、PDF）／匯入 1–100 集影片」；只問比例、畫面風格、導演風格 | 其他設定延後到需要時才問 |
| 頂欄 | 專案名、集數切換、常駐四站步驟條「劇本—設定—分鏡—短片」、AI 助手、餘額 | 步驟條同時是進度條（我們不借，見固定決策 1） |
| 劇本 | 分場大綱（歷史版本、場次數、字數）＋可直接編輯的正文；未確認時有黃色提示；確認前說明會發生什麼 | 每站一顆主按鈕 |

| 分鏡 | 左：鏡頭號與時長、出鏡角色（角色＋造型下拉＋聲音）、場景、道具、白模預演（可選）、故事板（可選）；中：分段鏡頭文字（【鏡頭】【畫面】【表演】【台詞】【聲音】），角色和道具是帶縮圖的 @ 標籤，生成列標價；右：結果與歷史；底：膠片條 | 「用了什麼｜怎麼拍｜結果」三欄 |
| 價格 | 角色圖約 $0.11、場景圖約 $0.16、28 秒影片約 $8.09 | 便宜的先定案，貴的最後才花 |

觀察到的弱點（本規格要避開或補上）：

- 流程很線性；回頭改稿時，已生成的素材怎麼處理看不出來。
- 分鏡頁中央是大段文字，視覺參考是「可選」且放在左欄最底；花大錢之前能看到的畫面很少。
- 一個鏡頭號是一整段多切點生成，只想改其中一個切點，可能要整段重生。

### 1.3 必須在實作前理解的陷阱

**A. 綁定寫回要逐字保留句子。** `@代碼` 在鏡頭提示詞裡的位置本身就是語意（例如「`@CAST-01` 把 `@PROP-01` 轉向 `@SET-01` 的圓頂」）。`PUT /shots/{id}/assets` 會把代碼全部刪掉再附加到句尾，破壞句子，所以 R2 不得使用它。改造型只換那個代碼的後綴；移除只刪那個代碼和因此多出的空白；加入則附加在句尾。其他文字逐字不變。

**B. 寫入要走表格自己的提交。** 鏡頭詳情屬於 sheet surface（`SheetWorkspace.jsx`），它有自己的未提交狀態、鎖、復原與衝突處理。R2 的寫入要走同一個儲存格提交（跟現在的「編輯」一樣），不要另外呼叫 story API 繞過表格狀態，否則畫面上的表格會跟後端不同步。

**C. 代碼可能出現在別的欄。** `shot_view` 會掃整列所有儲存格找 `@代碼`，但 R2 只改 `Action & Audio Prompt`。如果同一個代碼也出現在 `Director Take Notes` 等欄，移除後它仍會留在 `assets` 裡；出場區塊要明示「也出現在：備註」，不能假裝已經移除。

**D. 大小寫與變體。** `asset_view` 會把代碼轉成大寫（`CAST-01:NIGHT`），提示詞裡則可能是 `@CAST-01:night`。比對一律先轉大寫（`assetReferences()` 已經這樣做）；寫回時，原句其他部分的大小寫保持不動。

**E. 同一張卡只能有一個在途任務。** R1 以 `assetId` 為鍵：在途時，那張卡的「生成」停用；重新整理後從 sessionStorage 恢復；只在該任務結束時刷新那一張卡和目前檢視中的詳情，不整頁重載。批次補圖的 task group 只存 `taskIds` 與 `assetCodes` 兩個陣列；兩者目前依同一順序建立，若要靠順序對應到卡片，必須先確認並加測試，不要默默依賴。

**F. `createdAt → finishedAt` 含排隊時間。** 預估只能說「最近幾次從送出到完成約 n 秒」，並寫出樣本數；少於 3 筆就顯示「時間未知」。

**G. 舊鏡頭沒有 `sceneId`。** 種子資料與舊鏡頭可能沒有場次；R5 的場次篩選要把這些素材歸到「未分場」，不能讓它們消失。

**H. 規劃秒數不是成片長度。** 拆鏡時新鏡頭的預演規劃預設每鏡 4 秒；實際影片長度由出片工作流程與節奏台修剪決定。R13 的預估只能稱為「規劃秒數」，不能說成片會是這個長度。

### 2.2 明確不做

- 常駐步驟條、確認後才解鎖下一站、每次換空間都跳確認對話框。
- 以「多切點整段生成」作為鏡頭單位。之後若接上支援多切點的模型，再另議「相鄰幾鏡合併送出」，不改鏡頭身份。
- 吉祥物式的浮動聊天助手；只借「依位置換的快捷動作」。
- 匯入影片反推劇本。
- 以金額為中心的介面；沒有報價時自行估算金額；自動付費、自動改用閉源卡、自動重拍。
- 以真實人名命名的畫風或導演風格預設。
- 新的素材資料表、鏡頭綁定表或新的頂層空間。
- 依目標長度自動改寫每鏡秒數（見 1.3 H）。

- **R1 背景生成**：按「生成」後畫面立即可以操作；該卡與檢視都顯示「生成中」與取消（`POST /tasks/{id}/cancellations`）；失敗時顯示原因與「重試」。可以連續替好幾張卡生成；切卡、編輯、切回劇本檢視都不受影響。批次「生成缺的參考圖」維持現有 task group 行為；能可靠對應時，卡片也顯示其中各張的狀態（見 1.3 E）。上傳與儲存仍可用 `run()`，但停用範圍只限該請求進行中，且不得涵蓋其他卡片的生成。
- **R5 場次篩選**：牆頂多一列「場次」：預設「全部」；另一顆是目前焦點場次（麵包屑上的場次，沒有焦點時隱藏）。選了場次，只顯示 `sceneIds` 含該場的素材；沒有任何場次的素材在「全部」與「未分場」下顯示。這個選擇和檢視一起記在 `rememberWorld()` 的 sessionStorage。
- **R8 生成列**（包 B）：見 3.4。角色檢視裡的「生成」用外框按鈕、不是主按鈕樣式，因為這個畫面的主按鈕仍是「更新分鏡並進片場」。
- **R9 外觀屬性**（包 B）：外觀分「屬性」與「文字」兩個分頁。屬性分組：基礎（性別表達、年齡段、地區／文化背景、膚色）、臉與髮（臉型、髮型、髮色）、體型（身高、體態）、服裝（上身、下身、鞋、配飾）。選完按「套用到外觀」才改文字；如果文字被手改過，先問要「取代」還是「附加」，不默默覆寫。第一版不另存屬性。
- **R10 畫風**（包 B）：左欄底部的「16:9 · 畫風」與對話框裡的畫風都用樣張卡挑；素材或鏡頭用了非全局畫風時，標示畫風名稱。
- **R12 就地編輯**（包 B）：造型縮圖列的最後是「＋」方塊（名稱、種類：服裝／姿勢／造型、描述）；選了某個造型，可以改名、刪除，刪除前先列出用到這套造型的鏡頭數並確認。聲音、狀態、備註直接在檢視裡改（收在「更多資料」）。卡片加上角標，例如「2 套造型沒圖」。
- **R12 版面（修訂）**：這個檢視是整個畫面裡資訊量最大的東西，不放在窄側欄，而是照 RunningHub 的主從面板：沒選卡片時，牆佔整個主區，右欄只有進度與主按鈕；選了卡片（不自動選第一張），右側面板長到約 3/5 寬（牆 `minmax(300px, 2fr)`、面板 `minmax(500px, 3fr)`），牆縮成緊湊的選卡區。面板標題列有名稱（選了造型就接著顯示造型名稱）、種類、狀態、「上傳圖片」與「×」，按 × 回到整面牆。視窗窄於 1100px 時整個工作室堆成單欄，維持原本的行為。
- **R12 編輯面板（第二次修訂：描述是主角）**：第一次修訂只是把面板放大，裡面仍是左圖右表單，而且一位角色只看得到一張圖、造型是一排小按鈕。照 RunningHub 的角色編輯重排成由上往下一疊，而且面板「編輯你選的那個對象」，不是只編輯卡片本身：
  - **大圖與圖片欄**：大圖旁邊列出這個對象的全部圖片（`GET /assets/{id}/images`：歷史版本加候選圖；主圖在最上面，其餘新的在前，標題旁是張數）。點一張只是預覽，大圖下方出現「預覽中，還不是主圖」與「設為主圖」，按了才送 `PUT /assets/{id}/selected-image`，因為主圖就是鏡頭實際會用的那一張。一位角色不只一張圖：本人與每一套造型各有自己的一組。
  - **造型列**：先是角色本身，接著每一套造型（縮圖加名稱），最後是「＋」方塊。選哪一個，下面的描述、圖片欄、生成參數、上傳與生成結果就都是那一個的；造型生成中，縮圖上會轉圈。改名、刪除只在選了造型時出現。新增造型的表單一開始帶入角色本身的描述，只需要改不同的地方。造型本來就是自己的素材列（`CAST-01:NIGHT`，有自己的 `assetId`、描述、圖片與生成選項），所以不需要新的 API。
  - **描述**：整個面板最大的一塊（角色描述／場景描述／道具描述），直接在裡面改，沒有另外的「編輯」按鈕。改過還沒存時顯示「尚未儲存」與「儲存」「還原」；只能看的人看到唯讀文字。「＋ 屬性」展開一個小面板放 R9 的屬性選擇，套用後文字進描述框成為未存的草稿，不默默覆寫。每個對象各有自己的草稿，切換造型不會弄丟另一個還沒存的字。
  - **一排生成參數**：描述正下方一列：工作流程、比例、解析度、畫風（只是標示），靠右是預估時間（或報價）與按鈕；只有寬度不夠時才換行，換行後按鈕仍靠右。描述有改過，按鈕變成「儲存並生成」，先存再生成，所以生成永遠用畫面上看到的描述；失敗後是「重試」。按鈕維持外框樣式，主按鈕仍是「更新分鏡並進片場」。
  - **更多資料**：聲音、狀態、備註、用到它的鏡頭與場次，以及「素材庫」「在試算表編輯」收進預設收合的「更多資料」；摘要列直接顯示聲音、狀態與鏡頭數，所以不用展開也看得到重點。
  - 1280×720 的視窗裡，大圖到生成列都在第一屏內，不需要捲動。

- **R4 階梯**：預演＝標題符合 `/previs|blockout/i` 的影片階段（跟 `ShotBench` 的判斷相同，不把來源影片當預演）；首幀＝`stageRole()` 為 1 或 3 的圖片階段；影片＝`stageRole()` 為 4 的影片階段。表格沒有 Previs 欄時不顯示預演格。影片格只顯示首幀或封面，不自動播放（符合 `docs/DESIGN_AND_DEV_GUIDELINES.md` §5.3）。點預演開「3D 片場」，點影片開「審片挑片」。表格有 Previs 欄但這一鏡還沒有預演時，在階梯旁顯示「還沒有預演」和一顆次要按鈕「先排預演」；主按鈕仍依 `primaryShotAction()`。
- **R2 出場**：依出現順序列出 `Action & Audio Prompt` 裡的每個 `@代碼`：縮圖（`buildAssetLookup()`／`resolveAssetReference()`）、名稱、造型下拉（`assetVariants()`，含「預設」）、移除。底部「＋ 加入」開素材清單（依類型分組、有縮圖）。缺圖的那一列帶「補參考圖」，行為跟主按鈕的「補參考圖」相同（開角色與場景牆並選中該卡）。表格唯讀或使用者沒有寫入權時只顯示，不給操作。
- **R3 標籤**：唯讀顯示的文字欄把 `@代碼` 畫成「縮圖＋名稱」標籤，點了開角色卡；找不到的代碼畫成「找不到 @XXX」的警示標籤，不能消失。按「編輯」後回到原文字與既有的預設片語標籤。
- **R8 生成列**（包 B）：鏡頭詳情的第一版只「顯示」這一步會用的工作流程、輸出與預估（唯讀），送出仍是主按鈕。要在鏡頭上切換工作流程，得先決定改走 `POST /shots/{id}/video-generations`（可帶 `appCode`），還是擴充 flow run 的卡片覆寫（見待決 3）。

### 3.4 共用生成列（R8，包 B）

| 欄位 | 角色與場景 | 鏡頭 |
|---|---|---|
| 工作流程 | 可選；來源是生成選項 API，依素材類型篩選；未設定的卡停用並顯示原因 | 第一版唯讀 |
| 輸出 | 依卡片宣告（例如參考圖；R14 之後加三視圖） | 唯讀 |
| 比例・解析度 | 卡片有對應 slot 才出現；預設跟集數設定 | 唯讀 |
| 跟隨全局畫風 | 勾選＝用集數的 `stylePresetId` | 唯讀 |
| 代價 | 開放權重：「約 n 秒（k 次）」或「時間未知」；Router 卡：報價＋「非價格鎖定」，失敗顯示錯誤 | 同左 |
| 送出 | 外框的「生成」（非主按鈕） | 由主按鈕送出 |

- 送出請求帶的 `appCode`、`modelParams` 必須跟畫面一致；production policy 為 `open_weights_only` 時，非開放權重的卡依待決 2 的決定處理。
- 寬度不夠時，生成列收成一行摘要（「FLUX 3 Klein · 參考圖 · 約 40 秒」），點開才展開。

### 3.5 頂欄空間選單（R6）

- `spaceNote()` 改成回傳可點的項目：
  - 故事與世界：〔劇本有改動 → 劇本檢視〕〔n 缺圖 → 角色與場景＋缺參考圖篩選〕。
  - 分鏡片場：〔n 待審 → 待審篩選〕〔n 缺圖 → 缺圖篩選〕。
  - 節奏台：〔拍好 n/m〕。
- 捷徑在選單裡是各自獨立的 `menuitem`，不得把按鈕巢狀在空間項目的按鈕裡；上下鍵走得到捷徑，Esc 關閉後焦點回到空間按鈕。
- 選單仍只在打開時出現；頂欄常駐控制數不增加。

### 3.8 新專案入口（R16）

- **位置**：首頁「新增專案」對話框分成「從故事開始｜從範本開始」，預設前者；範本表單照舊（待決 7：並列，不取代）。兩邊都保持掛載，切換不會清掉已輸入的內容。
- **從故事開始**：切換「一句話靈感｜小說／故事章節｜標準分場劇本」；一個大輸入框，可載入 `.txt`／`.md`（2 MB、50 萬字內）；畫幅比例；畫風樣張（來自 `/catalog/styles`，讀不到就用預設畫風）；名稱選填，留空取第一行前 40 字。「建立並開始」是這個對話框唯一的主按鈕，沒有內容時停用。
- **建立**：`POST /projects/api/projects`（`zerofield_studio` 範本），然後帶著輸入跳到 `/projects/{slug}/#story-world`；比例與畫風進故事頁的格式設定。[SPEC_16A](SPEC_16A_INTEGRATION_INTO_THREE_SPACE_STORY_WORLD.md) 的 V12 修正後，不再由故事頁 `PUT script`，也不再讀完便刪 sessionStorage。工作台先保留原文與固定交接 ID，每次寫入前把重試路徑、本文與鍵存成 checkpoint：點子／小說在同名私有來源為空時存入，劇本在工作中稿為空時使用區塊寫入；來源或稿件非空一律保留既有內容，另開私有另稿。伺服器確認且資源重新載入成功才清掉 pending；失敗可重試或下載原文。回應遺失時重播同一請求／鍵，不另外造一次寫入。收據期限為 24 小時且綁登入憑證；換憑證後不保證曖昧請求去重。文字會在建立分鏡前先到伺服器，但私有來源／另稿不等於製作來源，也不會自動生成。
- 純函式與交接在 `ui/src/startModel.js`，介面在 `ui/src/StartFromStory.jsx`，故事頁的接收在 `StoryWorld.jsx` 載入集數的那個 effect；交接去哪裡是 `storyHostModel.js` 的 `startHandOff` 決定，工作台收下私有來源文字的是 `AuthoringWorkspace.jsx` 的 `seed`。

## 4. 介面與資料契約

### 4.1 前端純函式（包 A）

放在純模型檔，方便直接用 `node --test` 測：

- `shotBindings(text, lookup)` → `[{code, base, look, name, imageUrl, missing, positions}]`，依第一次出現的順序；同一代碼出現多次合併成一列，記下所有位置。
- `replaceLook(text, code, nextCode)`、`removeBinding(text, code)`、`addBinding(text, code)`：只動目標代碼。`removeBinding` 收掉刪除後產生的連續空白，以及標點前多出的空白；`addBinding` 附加到句尾（前面補一個空白）。三者對同一輸入的結果固定。
- `mediaLadder(parsed, row)` → `[{key: 'previs'|'frame'|'video', stage, media}]`；沒有對應欄的格不回傳。
- `sceneFilter(items, sceneId)`：`sceneId` 為 `null` 回全部；`'__unscened'` 只回沒有 `sceneIds` 的素材。
- 背景生成登記的讀寫：sessionStorage 鍵 `zf.gen:<epId>`，內容 `{[assetId]: taskId}`；所有存取都包 try/catch，沒有儲存空間時只放在記憶體。
- `spaceShortcuts(key, counts)` → `[{label, target}]`，取代 `spaceNote()` 的字串（`spaceNote()` 可保留給舊的呼叫者）。

### 4.2 後端（包 B）

- **生成選項**：新增 `GET /assets/{assetId}/generation-options` 與 `GET /shots/{shotId}/generation-options`，回傳：

  ```json
  {"apps": [{"appCode": "FLUX3_SOUL_CAST", "name": "FLUX 3 Klein", "tier": "open_weights",
             "configured": true, "reason": null, "outputs": ["REFERENCE"],
             "slots": {"aspectRatio": true, "resolution": ["1k", "2k"]},
             "estimate": {"seconds": 41, "samples": 5}, "quotable": false}],
   "defaultAppCode": "FLUX3_SOUL_CAST",
   "style": {"stylePresetId": "88123", "name": "Sci-Fi Noir Anamorphic"}}
  ```

  - `apps` 依素材類型篩選：卡片可宣告 `usage_scopes`，沒宣告的維持出現在所有範圍，以保相容。
  - `slots` 由卡片 `nodes` 的 `slot` 名稱推得；沒有就省略該欄。
  - `estimate` 取同專案、同 `appCode` 最近 20 筆 `SUCCEEDED` 任務 `finishedAt − createdAt` 的中位數；少於 3 筆為 `null`。
  - `quotable` 只在 Comfy Router 卡為 `true`。
  - 不回傳任何金鑰或供應商設定細節。
- **`GET /catalog/apps` 的 `usageScope`**：依同一宣告真正篩選；沒帶參數時行為不變。
- **`PATCH /assets/{id}`**：另外接受 `voice`（第 4 欄）、`status`（第 5 欄，必須在 `doc_schema.STATUSES` 內，否則 400）、`notes`（第 6 欄）。造型列的 `kind` 由 variants API 管理，`PATCH` 不得覆寫。只送 `name`／`prompt` 的舊客戶端行為不變。
- **拆鏡預估**：新增 `POST /episodes/{id}/storyboard-estimates`。
  - body：`breakdownModes`（要比較的拆法清單，預設為 UI 列出的三種）、`targetSeconds`（可選，10–1800）、`scriptContent`（可選，最多 500,000 字；有帶就估算這份未儲存的草稿，否則用已儲存的劇本）。
  - 回傳 `{modes: [{breakdownMode, shotCount, newShots, keptShots, plannedSeconds}], targetSeconds}`。
  - 用跟 `build_shots()` 相同的場次切分與 `scene_shot_beats()`，`newShots`／`keptShots` 依「保留既有鏡頭、只補缺的節拍」的規則計算；`plannedSeconds` 是新鏡頭的預設規劃秒數加上既有鏡頭的規劃秒數。
  - 只做確定性計算：不寫入、不呼叫模型。
- **畫風樣張**：`STYLES` 每一項加上 `sampleImage`（隨前端建置發佈的靜態檔路徑）。樣張用開放權重工作流程產生，SFW，沒有真實人物；缺樣張時 UI 顯示名稱卡。

### 4.3 錯誤與狀態

- 生成任務失敗：卡片與檢視顯示 `error.message`，保留「重試」；取消成功顯示「已取消」，不算失敗。
- 生成選項載入失敗：生成列退回「只有預設工作流程」，並顯示「無法載入選項」；不阻擋生成。
- 報價失敗：顯示錯誤，不顯示金額。
- 拆鏡預估失敗：對話框照常可以確認，只是預估區塊顯示「無法預估」。
- 新文案全部加到 `en.json` 與 `zh-TW.json`，兩邊的鍵與參數一致（`ui/tests/i18n.test.mjs` 會檢查）。
